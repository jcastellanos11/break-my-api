# Break My API · UX audit

**Design review, 25 November 2026 · P1.5.1 baseline**

**First change to review:** Keep Start, status and the first completed second together. The product already answers “what happened?” accurately. On the phone the user must pass the settings for almost every possible experiment to reach that answer.

## What was inspected

- Opened each of the three owner-supplied PNGs locally and compared the visible compositions. They describe single screens. Their controls and animations were not exercised. The reference images remain private working material.
- Read the project decisions, engine and educational specifications, design brief, current React views, locale resources, CSS, controller, engine interfaces and tests. Source observations below identify the component or selector to revisit.
- Chrome rendered the existing local P1.5.1 build-review fixture. Its accessibility tree exposed Playground, Learn, Fundamentals, the selected 503 article, Glossary and About in EN and ES at 1100 and 390 CSS pixels. Visually inspected the top of Playground and Learn in the scaled comparison sheet. On the Spanish phone catalog, entered 429 with 503 selected and inspected the resulting heading, input and link. The fixture supplies route inputs locally.
- The current checkout passed **83 tests in six files**. These cover behavior such as replay, keyboard dismissal and history traversal. They do not measure comprehension. Live HTTP preview failed with `listen EPERM: operation not permitted 127.0.0.1:4173`. No hosted refresh, physical phone, screen-reader speech, pixel-by-pixel overflow sweep, or live animation audit was performed.
- **Heuristic verdict: 3/5 for finding and comparing evidence.** A reviewer can identify the scenario, start action and distinct metric groups. The mobile order and the disconnect between a search result and the selected article add navigation work. This is a design judgment from the inspected tasks, not participant research.

## Findings by priority

High affects a primary experiment or lookup task. Medium affects repeated interpretation or discovery. Low improves a secondary reading task. Benefits are hypotheses for review. Risks describe what a redesign could break.

| Priority / task | Current evidence | Proposed change and expected benefit | Regression to guard against |
|---|---|---|---|
| High · see the effect of Start | In the ready phone fixture the toolbar and introductory copy occupy the upper section. In `Playground.tsx`, `Learning` precedes `.lab-grid`, and settings precede observations. At ≤700px the grid becomes one column. | Put the three last-second measures directly below the run bar. Make controls a clearly labeled disclosure on the phone. A beginner can start and watch the first sample in one place. | Moving a disclosure can strand the tour link to controls. Opening it must reveal and focus the target without editing the run. |
| High · interpret a number | `Metrics` correctly groups last second, since start and current. All use the same article, definition-list and value styles. Effective instances appear in both capacity and scaling. The two charts follow the entire stack. | Lead with demand, successful throughput and observed p95. Put “now” capacity next to the primary chart, then run totals. A user can distinguish a rising total from rising demand. | Losing the interval bounds, conflating processing with waiting, or showing a zero p95 before a success would change the meaning. |
| High · look up a second HTTP code | `Explorer` places the selected article before the filters and list. In the ES 390px fixture, searching for 429 produced a matching 429 link while the article heading still read 503. The filter itself worked. | Keep the query and selected result visually distinct. Provide a return-to-results action on phones. The reader can choose a new answer while keeping their search. | Automatic selection on typing would rewrite a shared URL and create surprising Back steps. |
| Medium · choose a control | In `Playground.tsx`, autoscaling appears before traffic. A single ranges loop interleaves traffic, instance count, slots, service, queue and conditional cache/limiter fields. Enabling scaling also exposes policy prose. | Group by demand, origin capacity, and protection. Summarize active settings when collapsed. Easier to find the one lever that tests a hypothesis. | Reset is a destructive scenario action. Keep its explanation beside the selector. Preserve disabled states and accepted work. |
| Medium · find explanations | `Help.tsx` already supports button activation, Escape, blur, outside click and focus return. CSS anchors the box to settings or an observation article. The same question-mark mark serves fields and measures. The metric link is a separate arrow. | Place each disclosure immediately beside its named value, distinguish “explain” from “open HTTP reference,” and preserve a visible focus ring. On narrow cards use an in-flow note. | An info button inside a slider/checkbox label can change a value. Moving focus on every published tick can interrupt reading. Placement risk inferred from CSS, not an observed clipped popover. |
| Medium · recognize actions and outcomes | The rendered Learn titles and active nav use green. `Plots.tsx` defines its own four series colors and dash patterns. Current text values and chart legends carry the semantics. | Keep a single action treatment and assign consistent labeled outcome tokens to chart keys, summaries and later branches. This lets users follow 429 across views. | Preserve distinguishable strokes, numeric codes and the accessible chart table. A green success label must not suggest that every arrival succeeded. |
| Medium · read supporting text | `global.css` sets safety copy to 11px, benchmark to 10px, lab terms to .8rem and values to 1.2rem. The opening render shows the notice, a simulated pill, and another notice before metrics. | Keep one legible simulated notice by the run bar, use a shared label size, and spend the recovered vertical space on readings. | The welcome illustration and the measured Playground must each retain clear context when seen independently. |
| Medium · choose and read a lesson | Rendered Learn cards use the same border, green title and text treatment for three different tasks. `LearnCenter` renders Fundamentals as four articles using the same reader frame. | Differentiate “follow a request,” “look up a code,” and “define a term.” Give Fundamentals one reading column, with its existing examples separated from explanation. | Illustrations can push destinations below the fold or look like live telemetry. Keep small decorative motifs and localized text links. |
| Medium · scan definitions | `Glossary` renders every match as an article with heading and full definition. Search, locale-aware sorting and shared depth already work for all 20 terms. | Use compact term disclosures and keep search and depth together. Readers can scan names and open the term they need. | Preserve the original definitions, HTTP links and open term across a language/depth change. Expose expanded state to assistive technology. |
| Low · understand scope | About renders a heading, model paragraph, safety paragraph and configured repo link in `LearnCenter`; the shared paragraph rule permits 75ch. | Keep this short page. Give assumptions a descriptive heading and the repository link an identifiable destination. Easier to find model limits without leaving the app. | Excess framing could bury the simple explanation or imply production fidelity. |

## Preserve and validate

Keep native form labels, distinct 429/503 outcomes, chart dashes and text equivalents, the optional tour, localized empty states and one mounted controller. The current implementation already provides these. Protect them in the [implementation plan](UI_REDESIGN_PLAN.md).

For the first comparison, ask a beginner to start Traffic Spike, point to the waiting gauge, and explain a 503. Ask an experienced engineer which interval supplied p95 and whether a pending instance has slots yet. Repeat on a phone in Spanish. Record the first place each person looked, unnecessary scrolling and any incorrect interpretation. Use their observations to decide which disclosures open by default.
